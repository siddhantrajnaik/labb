# Labb v0.3 Functional

Labb is a local-first laboratory inventory and procurement application based on the supplied Labb prototype. Version 0.3 adds physical container/lot tracking, barcode-scanner workflows, chemical usage logging, reorder planning, expiry notifications, and PO/invoice reconciliation while preserving the v0.2 database and UI model.

## What v0.3 adds

- **Container/lot ledger** under every inventory item.
  - Unique `LABC-0000001` container codes.
  - Lot number, received/opened dates, expiry, storage, initial quantity, remaining quantity, status, and procurement source.
  - Existing v0.2 aggregate stock is migrated into one traceable `MIGRATION` container per stocked item.
  - Aggregate `inventory.current_stock` is reconciled from the container ledger for backward compatibility.
- **Barcode/QR scanner workflow**.
  - Resolve Labb item codes, SKUs, container codes, and `labb://...` QR values.
  - Designed for USB/Bluetooth keyboard-wedge scanners; scan into the focused field and press/emit Enter.
  - Direct actions from a scan: record use, inspect containers, or print a container label.
- **Container labels** with QR and Code128.
- **Chemical/consumable usage log**.
  - Quantity, project, purpose, notes, user, timestamp, and physical container allocation.
  - If no container is selected, stock is consumed by FEFO: earliest-expiring active container first.
  - Members are allowed to record usage; additions/stock corrections remain Admin-controlled.
- **Automated reorder suggestions**.
  - Uses minimum stock plus the previous 90 days of logged consumption.
  - Configurable reorder planning horizon, default 30 days.
  - Reports estimated daily use, days of cover, target stock, and recommended order quantity.
- **Expiry/low-stock notifications**.
  - Generated from active physical containers and aggregate stock.
  - Configurable expiry-notice horizon, default 90 days.
  - Users can acknowledge notifications; audit history records the acknowledgement.
- **Lot-aware procurement receiving**.
  - Receipt can specify number of physical containers, lot, expiry, and storage.
  - The received quantity is split equally across those generated container records.
- **PO/invoice reconciliation**.
  - Invoice reference, amount, date, payment status, note, and variance against PO total.
  - `MATCHED` when invoice variance is within max(INR 1, 0.5% of PO total); otherwise `VARIANCE`.
  - Quantity reconciliation shows ordered vs received per request item.
  - Requests cannot be closed before all ordered quantities are delivered.
- Analytics now includes consumption, reorder suggestions, and invoice reconciliation summaries.

All v0.2 features remain: users/roles, inventory, QR item labels, SDS and procurement attachments, purchase-order PDF, CSV/XLSX import, CSV export, full ZIP backup, audit log, vendors, responsive UI, and Windows PyInstaller build script.

## Default first-run accounts

For a **new database only**:

- Admin: `admin` / `ChangeMe123!`
- Member: `member` / `Member123!`

Both are flagged for password change. Set `LABB_ADMIN_PASSWORD` before the first launch to override the initial Admin password.

## Permissions

**Members** can view inventory/containers/vendors/analytics, scan labels, record usage, create procurement requests, download labels/POs/exports, attach files to requests, and acknowledge notifications.

**Admins** additionally control inventory creation and stock adjustments, physical-container creation, vendors, ordering/receiving/closing procurement, reconciliation, inventory/SDS attachments, bulk import, backups, settings, users, and audit logs.

Authorization is enforced by the FastAPI backend.

## Run from source

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run_labb.py
```

Runtime data are stored outside the program folder:

```text
%USERPROFILE%\.labb\
├── labb.sqlite3
└── attachments\
```

Set `LABB_HOME` or `LABB_DB` to change the location.

## Build Windows EXE

On Windows:

```bat
build_windows.bat
```

Output:

```text
dist\Labb.exe
```

The executable does not embed the user database, so replacing/updating the EXE does not overwrite `.labb` data.

## Upgrade from v0.2

v0.3 performs an additive migration. It creates:

- `inventory_containers`
- `usage_log`
- `notifications`

and adds invoice/reconciliation fields to `requests`.

For each pre-existing inventory item with positive stock and no container records, v0.3 creates one migration container whose remaining quantity equals the existing aggregate stock. Existing inventory, stock values, users, vendors, requests, receipts, attachments, and audit records are retained.

**Create a v0.2 backup before upgrading a production laboratory database.** See `MIGRATION_RESULT.json` for the automated preservation check.

## Important quantity assumption

Labb v0.3 assumes the aggregate inventory unit and the physical-container quantity unit are compatible. For example, if an item is tracked in `mL`, its containers should also be recorded in `mL`; if it is tracked as `bottles`, physical receipt/usage should be recorded in bottles. Automatic mass/volume/unit conversion is not performed in v0.3.

## Bulk import

CSV/XLSX import remains supported. Imported `current_stock` is now backed by container-ledger records so aggregate stock and physical stock remain synchronized.
